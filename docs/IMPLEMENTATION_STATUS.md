## 上线前必要事项

目前用户没有 Hostaway 登录账号，所以真实接入、账户内行为、写 API、webhook 注册均未验证。当前 adapter 只实现 reservations 读取与 shadow 存储，不声称覆盖所有公开 API。当前没有自动 shadow promotion，也没有启用后台全量同步。

其余 44 项功能地图里的市场定价、渠道直连、SMS/WhatsApp、门锁、入住身份、签约、加购、优惠券、完整库存池、细粒度员工权限等未在本批实现；已有基础模块继续复用，不把目录当完成状态。付费服务、第三方账号及授权资格需分别确定。

## 兼容与人工复核

新默认：OPS_SCHEDULER_ENABLED=0、OPS_MESSAGE_DISPATCH_ENABLED=0、OPS_OWNER_EMAIL_ENABLED=0。这些是可控升级默认值，若直接部署而未迁移配置，会暂停既有自动任务/邮件。上线时需要明确恢复哪些自动化，并逐订单设置 notifications_enabled；不能默认开启历史回填。time_zone 默认 UTC，真实物业应核准其本地时区。佣金必须显式录入（0 表示约定免佣金，空表示未知）。结算金额仍以现有 AUD/退房所在月为基线；未实现多币种和应计跨月分摊。

旧无 source_feed_id 记录只在对应物业/渠道唯一 feed 时认领；多 feed 歧义直接留待映射。影子层缺少 updatedOn 的变化会保留旧版本，不盲目覆盖；后续需人工或详情刷新解决。SQLite/PostgreSQL 对并发和迁移行为不同，当前测试仅 SQLite；PostgreSQL 尚待隔离服务验收。

消息状态 sending/unknown 和业主邮件 unknown 应先在发送端核对；本批不提供“盲目重发”按钮。已发消息/邮件不能通过回滚撤回。

## 第二批：人工复核（2026-10-21，本地未发布）

新增带依据的管理员复核表单和近期历史：来源缺失可确认保留/取消；清洁改期可采用新时间或保留人工安排；发送结果不明可按发送端记录确认已发或关闭且不重发。表单包含用户/动作/记录状态绑定的 15 分钟签名 token，单次使用；旧版本、跨用户、跨来源提交被拒绝。

每个决定保存操作人、依据、前后状态哈希与记录 ID。取消订单时，未完成清洁任务改为归档保留历史，不再删除；清洁门户和待办排除归档任务。已完成工作不能被改期，主管确认保留原安排后，同一次订单版本不会重复告警；下一次改期重新告警。活跃发送不能被立即人工覆盖，超过一小时的发送 claim 才进入复核。这仍不能证明外部邮件已发，必须人工检查邮箱。

数据库连接修复作为独立生产补丁，通过 PR #1 发布；本批人工复核与此前大功能分支分开验收，未混入该生产补丁。

## 第三批：本地房源日历与房晚统计（2026-10-21，未发布）

新增管理员日历 /operations/calendar 和只读 API /api/ops/calendar。按日期与物业筛选（1–62 晚）；显示确认预订、封锁、到离店、实时计算的时间重叠、来源待复核。退房日不计入住夜；取消记录排除，来源失联订单保留占用。以去重房晚计算本地预订房晚比例，封锁降低可售分母；存在冲突/无效日期或零可售时不报比例。只展示逐物业数字，不叠加父子房源，不声称真实入住率、市场库存或 OTA 实时可售量。不暴露客人姓名、门码或门户链接。默认日期为 Brisbane 当地日期。

## 第四批：维修与通用工单（2026-10-21，本地未发布）

新增 /operations/tasks：按房源/状态查看工单，记录维修、检查、客人请求及其他运营问题；支持优先级、在职员工指派、Brisbane 日期口径的截止日、逾期标识。每次保存有备注、操作人和任务状态快照。列表展示前 100 项并提示缩小范围；详情展示最近 100 项历史，旧事件留在数据库。

状态：open → in_progress → done；open/in_progress 可取消，done/cancelled 可重开。完成需先开始工作，关闭记录保留，重开清除当前 completed_at，历史完成依据留在事件中。采用 15 分钟签名表单、用户与记录版本绑定、单次提交唯一约束和版本条件更新；拒绝旧版本覆盖、重复创建、跨来源提交和非管理员访问。工单创建后不能移到另一房源。

新增 work_orders/work_order_events 两张表，随 create_all 增量创建，无旧字段覆盖，无删除功能。运营总览增加逾期工单数量。只供管理员使用，不代表被指派员工已收到通知或有权限登录此工单界面。不会自动封锁库存、发信或计入业主账单。周期规则、附件照片、工作时长/材料费与供应商门户尚未实现。

## 第五批：工单检查清单与验收（2026-10-21，本地未发布）

新增 work_order_checks 表；每张工单最多 50 个检查项，可区分必做/选做，逐项勾选或改回待检查。勾选记录操作人、UTC 时间和依据备注；新增与每次状态变更在工单事件中保存完整清单快照。历史保留，当前不提供删除或改写检查项标签的接口。

必做项未完成会拒绝结单；选做项不阻止。已完成/取消的工单不能改清单，需要先重新打开；重开会清空当前勾选与验收人，要求新一轮验收，过去结果保留在历史。新增项默认必做。原有无清单工单保持原有完成流程，不自动虚构验收要求。

清单提交使用独立用途签名 token，绑定用户、任务及版本；与工单修改共用父记录版本条件更新，清单改变会使旧工单表单失效，拒绝错任务检查项、重复提交及过期/旧版本覆盖。更新与历史原子提交。仅管理员可访问，不新增员工或第三方权限。页面表单调整为逐行显示并更新静态样式版本。
