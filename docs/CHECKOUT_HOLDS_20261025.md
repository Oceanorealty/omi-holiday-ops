# Fixed sandbox checkout inventory holds

A verified new sandbox checkout now atomically persists a 15-minute inventory hold before requesting a Stripe test PaymentIntent. The hold has one fixed expiry; retries and saved-checkout recovery do not renew it. A quote does not hold inventory. If an ambiguous creation attempt has no persisted provider ID when its hold expires, creating another intent is refused and operator review is required. Existing intents remain recoverable for status review.

Local public quotes/calendars and direct reservation writes share the existing stock guard and consume active holds with explicit shared-resource quantities. Fulfillment excludes only its own hold and rechecks bookings, other holds and restrictions under the same lock. A late success can confirm if stock remains free; otherwise the existing idempotent sandbox conflict-refund path applies. Terminal payments stop consuming hold stock, without deleting the lease record. Calendar counts show holds separately from reservations and occupancy. Short holds are deliberately excluded from iCal exports because external calendars cannot expire them reliably. Stock mapping/timezone changes wait for active leases to end.

The sandbox checkout displays a server-derived countdown, prevents a new browser payment after expiry, and preserves the original attempt identity for status review. Expiry never marks a payment failed. Expired creating/awaiting attempts appear in the admin review queue. The phone form has labelled, stacked fields. No live credentials, live payments, external OTA reservation or automatic guest-message delivery are introduced.

Validation: 539 tests passed with disposable PostgreSQL, including concurrent checkout creation, shared quantity accounting, fixed expiry/replay, late callbacks, direct reservation exclusion, privacy, adjacent night boundaries and iCal exclusion. Existing late-success concurrency tests now explicitly model expired earlier holds. A real Stripe Sandbox browser flow used a separate synthetic local property and the official test card for A$2, rejected a competing attempt, received the signed callback, created one booking/account with two ledger entries, and ended the active hold. No real money moved. Browser width 390px, document width 375px.

Remaining boundaries: production payments remain disabled. Production rollout still needs the existing live-payment work plus abuse/rate controls for unauthenticated hold creation; this release does not claim full website checkout readiness. There is no guest cancellation/release operation in this change: abandoned holds expire automatically, while uncertain payment outcomes need review. Before rolling back to code that ignores holds, disable sandbox checkout, wait for active holds to expire, and reconcile submitted payments. Preserve the additive public_checkout_holds table.
