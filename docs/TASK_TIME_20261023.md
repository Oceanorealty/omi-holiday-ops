# Task work-time intervals — local development candidate

Administrators can record start/stop timers on behalf of active named staff for operations work orders. Each staff member can have one running timer across all work orders. Task edits leaving In progress or changing the assignee stop running intervals transactionally; a failed completion rolls the entire operation back. Reopening never silently resumes old intervals. Mistaken entries can be voided with retained records and command audit.

Reports use UTC date boundaries and clip intervals to the selected range. Stopped seconds and provisional running seconds are separate. Filters cover property and staff, including historical inactive staff, with CSV export and formula-safe staff cells. Queries fail with a clear narrowing request beyond 10,000 intervals. Signed task-version forms, admin checks, same-origin validation, database uniqueness and the shared write guard protect timer actions.

No employee self-service, payroll, attendance verification or automatic labor expenses are introduced. The legacy cleaning-dispatch module is separate; this applies to operations work orders. Full field-worker permissions and cleaning integration remain pending. Storage is additive (`task_time_entries`); there is no change to existing table columns or production settings. This candidate remains local and not deployed.
