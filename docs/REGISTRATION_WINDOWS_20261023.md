# Guest registration and booking windows

Guest registration adds configurable per-property required adult names and up to 20 text questions. Prefix a required question with `*`; labels are limited to 240 characters, answers to 2000. Guest names are limited to 160 characters, and declared adults plus children must match total guests when required. This is a guest declaration, not identity verification or proof of attendance. Identity document/selfie uploads and certified verification remain unimplemented.

Draft and submitted records are separate states with immutable event snapshots. Drafts never satisfy required registration. Tokens bind the booking dates/status/property, policy revision and latest registration version. Policy or booking changes invalidate current registration and loaded forms. Older records remain in event history. The existing arrival-information gate requires both current arrival details and required registration, with matching total guests. Guest and administrator pages use no-store; unknown/cancelled portal links cannot submit; stays past checkout cannot update.

Administrators can review current/draft information and 50 recent historical snapshots. CSV export covers submitted current records by property and local arrival-date range (end excluded, 366 days, 5000 records maximum), marks stale records and neutralizes spreadsheet formulas. Drafts are excluded, including registrations changed back to draft; prior formal submissions remain in event history. No public listing API includes registration data. No external messages, identity provider or notifications are sent.

Direct-booking windows configure minimum calendar-day notice, inclusive maximum advance days and an optional same-day cutoff in the property timezone. Limits are 0–1095 days. Unconfigured properties preserve prior behavior. Saved rules prevent past arrivals, apply to quotes and refreshed request validation, and recheck new bookings, changed dates and restorations under the existing write guard. Contact-only edits preserve existing dates. Calendar responses distinguish closed arrivals from occupied physical inventory. Invalid configured timezones fail closed. These rules are local only; OTA publishing remains unconnected. Rolling-hour lead times are not implied by calendar-day notice.

Additive registration_configs, guest_registrations, guest_registration_events and booking_windows tables; existing tables unchanged. Startup first snapshots existing tables to ops_backup_20261023_gapfill. This same-database copy is not an offsite backup. Rollback uses the prior application deployment, which ignores additive records. The new guest links would be unavailable after rollback.
